# 🔗 URL Backend - URL Shortener Application

A full-stack URL Shortener built using Node.js, Express.js, MongoDB, EJS, JWT Authentication, and Mongoose. The application allows registered users to generate short URLs, track click analytics, and manage their URLs securely through authentication and authorization.

---

# 📖 Project Overview

The URL Backend project is designed to convert long URLs into shorter, manageable links. Users can create accounts, log in securely, generate shortened URLs, and monitor analytics such as click counts and visit history.

The system uses role-based access control where:

* NORMAL users can create and manage their own URLs.
* ADMIN users can view all URLs generated by all users.

# 📄 File-by-File Explanation

## index.js

Main entry point of the application.

Responsibilities:

* Creates Express Server
* Connects MongoDB
* Configures Middleware
* Registers Routes
* Handles URL Redirection
* Starts Server

Important Functions:

```javascript
app.use(express.json());
app.use(cookieParser());
app.use(checkForAuthentication);
```

These middleware parse requests and authenticate users.

---

## connection.js

Responsible for connecting the application to MongoDB.

```javascript
mongoose.connect(url)
```

Returns a database connection promise.

# 📂 Controllers

Controllers contain business logic.

---

## controllers/url.js

Handles URL operations.

### handleGenerateNewShortURL()

Purpose:

* Receives long URL
* Generates unique Short ID
* Stores URL in MongoDB

Example:

```text
Original URL:
https://google.com

Generated:
http://localhost:8001/abc123
```

---

### handleGetAnalytics()

Purpose:

* Fetch analytics for a URL
* Return click count
* Return visit history

Response:

```json
{
  "totalClicks": 10,
  "analytics": [...]
}
```

---

## controllers/user.js

Handles user-related operations.

### handleUserSignUp()

Purpose:

* Create new user
* Store user details

Input:

```json
{
  "name":"John",
  "email":"john@gmail.com",
  "password":"123456"
}
```

---

### handleUserLogin()

Purpose:

* Authenticate user
* Generate JWT Token
* Store Token in Cookie

# 🔄 Application Workflow

1. User Registers
2. User Logs In
3. JWT Token Generated
4. Token Stored in Cookie
5. User Creates URL
6. Short URL Generated
7. URL Stored in MongoDB
8. User Shares Short URL
9. Visitors Click URL
10. Click History Stored
11. Analytics Available

---

# 🔐 Authentication Flow

```text
Login
   ↓
JWT Token Generated
   ↓
Stored in Cookie
   ↓
Middleware Verification
   ↓
Access Granted
```
